# 棋墩墩

<p align="left"><img src="public/icon-512.png" width="72" height="72" alt="棋墩墩图标：一摞四枚圆棋立在棋盘上"></p>

我家大人玩的「掀棋 / 打棋摞」——用中国象棋的 32 枚棋子玩的一种吃墩游戏。这个仓库是它的**纯规则引擎 + 命令行版 + 浏览器图形版**，规则全部写死在一个 `rules.json` 里，改规则不用碰代码。

零运行时依赖：引擎和界面都是手写 TypeScript，构建只用 Vite，产物 JS 38 kB（gzip 14.6 kB）。

## 怎么玩（规则速览）

**棋子**：32 枚、7 个职级、14 档。兵卒 5+5，炮/车/马/相/士各 2+2，将帅 1+1。大小一律**黑 < 红**：

```
卒 < 兵 < 黑炮 < 红炮 < 黑车 < 红车 < 黑马 < 红马 < 黑象 < 红相 < 黑士 < 红仕 < 黑将 < 红帅
```

点数只用来抽签，与大小无关：兵卒 7、炮 6、车 5、马 4、相 3、士 2、将帅 1（红黑同点）。

**开局**：32 枚随机码扣成 8 摞（面朝下，不按大小排）。人数 2 人（每人 16 枚）或 4 人（每人 8 枚），3 人局不做。

1. **抽签**（全局只抽一次）：起抽人从 8 摞里挑一摞，摊开后点哪张抽哪张，看翻出的点数，从自己开始顺时针数，数到谁，谁就是这 8 摞怎么分的**处置人**，也是第一轮的先出人。这张牌只在抽的当场是明着的，进手之后跟着扣。
2. **分牌**：处置人从三种拿法里选一种——层层轮流分 / 整摞轮流拿·从左 / 整摞轮流拿·从右。不能指名把某一摞给谁。
3. **吃墩**：成组出牌，同职级同色手里有几张就出几张（兵卒最多 5 张），将帅这级允许跨色配对；对子也可以拆成单张出。
4. **结算**：必须全部打完才结算。收来的牌 4 张码一摞，**只比总张数**，多者赢，完全相同算和局。

**明棋**：出牌即亮。跟牌比场上当前最大那一家（不是只跟上家），且张数要对得上——单应单、对应对。手里有同张数且更大的**必须出**（拆对也得出），压不过就抵押。

**暗棋（扣棋）**：先出人决定这一墩出几张，牌扣着出，自己那套在桌面上也是扣着的。其余几家**同时**暗出：张数对得上就必须出，但**不要求比对方大**，可以故意喂小的。全员出完停约两秒再一起翻开，最大的那家把整墩收走。

**抵押**：压不过或凑不出同样张数，就弃相同张数给赢家（手里不够就有几张弃几张），弃的牌跟赢来的牌一起摞、一起计数。

**同档**：一样大不算和，顺时针靠前（先出）的那家赢。

**跨局**：下一局由上一局赢家起抽；打完并列（没人赢）签就不动，仍由上局那位起抽。

## 三种跑法

```bash
npm install          # 只有 typescript / vite / @types/node 三个开发依赖
```

### 1. 浏览器图形版（PC + H5 一套响应式）

```bash
npm run dev          # http://localhost:5199（端口钉死，撞了直接报错不偷偷换）
npm run build        # 产物在 dist/，纯静态，扔到任何静态托管都能跑
npm run preview      # 本地起 dist，Vite 默认端口
```

开局选人数 / 明暗 / 电脑难度。摸签、翻牌数点、分牌、出牌、翻墩收牌全程有动画；触屏和鼠标两条路径分开做（鼠标扫到哪摞哪摞摊开，触屏是「点那摞 → 摊开 → 点那张」）。

### 2. 命令行对战（你坐 P1，电脑坐其余）

```bash
npm run play -- --players=2 --mode=kou --level=hard
```

### 3. 电脑对电脑自我对弈（做统计用）

```bash
npm run selfplay -- --players=4 --mode=ming --levels=easy,greedy,hard --games=400
```

通用参数：`--mode=ming|kou`、`--players=2|4`、`--seed=N`；`play` 带 `--level=easy|greedy|hard`，`selfplay` 带 `--levels=a,b,c`（按座位逐个指定）和 `--games`、`--verbose`。默认一局接一局、上局赢家起抽，加 `--independent` 则每局各摇一次签。

### 校验

```bash
npm run verify       # typecheck + check + test，共 773 条断言
```

`check` 打印 14 档强度序、三种分牌法和明暗两栏规则，用来确认 `rules.json` 和代码没跑偏。

## 改规则

只改 [`rules.json`](rules.json)：职级名称、每级几张、牌堆每摞几张、明暗两栏的比牌规则、并列怎么判，全在里面。改完跑 `npm run verify`，规则断言会告诉你对没对上。

## 目录

```
src/core/    规则引擎（纯逻辑，不碰 DOM、不碰 Node API）
  game.ts      状态机：摆摞 → 抽签 → 分牌 → 一墩墩打 → 结算
  trick.ts     比大小、成组、能不能压
  view.ts      信息边界：每家只看得见自己该看见的，查隐藏牌直接抛错
  match.ts     跨局：赢家起抽、总账本
src/ai/      三档电脑：easy 随机 / greedy 只挑最省的牌 / hard 算期望收几枚
src/cli/     命令行版
src/web/     浏览器版
  board.ts     所有坐标与让位量的唯一来源（纯函数，零 DOM）
  pieces.ts    32 枚棋子的 DOM 与翻面/位移动画
  app.ts       流程控制器：开桌 → 一局局打 → 复盘 → 再来一局
  ui.ts        外壳与样式（名字条、按钮、日志抽屉、弹窗）
src/test/    rules.test.ts（规则）+ layout.test.ts（布局守恒，五种视口 × 2/4 人）
public/      图标：icon.svg 一张画到底，其余尺寸由 npm run icon 渲出来
```

## 实测（`npm run selfplay`，400 局、两种座位次序各一遍，只数唯一赢家）

| 组 | easy | greedy | hard |
|---|---|---|---|
| 2 人暗棋 | **46~53%** | 33~40% | 39~44% |
| 2 人明棋 | 19~21% | 36~59% | 40~44% |
| 4 人暗棋 | **23~25%** | 14~16% | — |
| 4 人明棋 | 9~13% | **27~30%** | — |

明棋里「刚好压得住的最小套」本身就是对的，所以 greedy 远强于随机；暗棋里 greedy 反而是三档最弱的——它既不判断赢面，又每墩都把自己的小牌往外送。座位基本中性。

## 已知边界

- **3 人局不做**（发不平，规则也没定）。
- 和局率不低（2 人 12~20%、4 人 20~24%）：实测过不是发牌结构注定的，是双方都没有拉开分差的手段。这版规则的态度是**平局就是平局**，不加赛、不重开、不靠先后判输赢。
- 浏览器版按桌面 Chrome 和五种视口（手机竖屏／窄窗／平板横屏／桌面／极窄）做布局守恒测试；iOS Safari、安卓真机的表现（`100dvh`、安全区、触屏延迟）得在自家设备上自己点一遍才算数，这里不替它打包票。
- 极端情况下（一家独吞整副 32 枚）收牌摞会排成 2×4 网格、小牌缩到 15px 左右，为的是守住那块固定地盘不压到别人的牌和名字条。
